1. 上传数据

支持 CSV 或 Excel（.xlsx）。必需列： Input Length、Concurrency； 可选列：Prefix Rate（缺失则整列记为 N/A，且不与有值的行对齐）。 其他指标列名会自动映射到 to_csv.py 规范 schema。Excel 仅支持单个 sheet，多 sheet / 旧版 .xls 会报错。 启动命令直接粘贴，支持 # 注释行与反斜杠续行。
请上传模型目录下的 config.json（就在 CSV 下方），用于推导参数量 / 权重占用 / 权重精度， 以及 context_length、dtype、quantization 等启动命令里通常不写的参数。 不传 config 时参数量需手填，其余推导列留空。
默认「单机 / 分布式」；若命令里出现 disaggregation / kv-transfer-config 等 PD 参数，会自动切到「PD 分离」， 需分别填写 prefill、decode（router 可选）。
result.csv 或 .xlsx（一次测试一份，PD 也是打整体服务的一份）
模型目录下的 config.json
context_length、dtype、quantization、 max-num-batched-tokens 这些参数启动命令里通常不写， 由 vllm / sglang 读模型 config 在运行时推导。上传它，这些列才有值； 不传则相应列留空，仍可正常入库。

2. bench（压测）参数

bench 框架与上面的 server 框架相互独立（sglang bench 可打 vllm server，反之亦然）。 上传 CSV 后会按 spec decoding 列是否有值自动识别：仅 vLLM 列有值→vllm，仅 SGLang 列有值→sglang； 两者都有 / 都无则需手选。
是否 flush cache 无法从 CSV 推断，必须手动选择（flush=冷启动无前缀命中，不 flush=复用缓存，结果差异大）。 Prefix Rate 已下沉为 CSV 行键，请写在表格里；本表单不再单独填写。

3. 填写模型服务信息

描述本次推理服务部署的模型与运行环境。框架决定用哪套启动参数提取规则与默认值回填。 参数量、权重占用、权重精度三项由上传的 config.json 推导， 选好文件后会在上方显示推导结果，核对无误就不用填。填了以填的为准（不一致时提交后会告警）。 未上传 config.json 时参数量必填。
入库后即可在对比助手中按维度查询该次测试。
