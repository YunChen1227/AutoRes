# 测试铁律：先测完、再汇总、再请示（禁止边测边改源码）

## 绝对禁止（违反即失败）

1. **测试/验证阶段禁止修改业务源码**（`.py` / `.sh` / `.yaml` / schema / 前端 / 配置模板等）。
2. **禁止**因「本地跑不通」就改代码——本地环境与用户运行环境**未对齐**，不能当作改代码依据。
3. **禁止**测一条、改一条、再测一条的循环；**禁止**未汇总就向用户提交 patch。
4. **禁止**把「测试辅助脚本/fixture」写进仓库业务目录并长期保留（见下方允许项）。
5. **禁止**在未向用户展示完整错误汇总前，声称「已修复」或「应该没问题了」。

## 允许的操作（仅限测试阶段）

| 允许 | 说明 |
|------|------|
| 只读 | `git diff` / `git status` / 读文件 / grep |
| 运行 | 执行现有脚本、命令、测试（用用户环境同款命令，见下） |
| 临时文件 | 仅在 `/tmp`、`%TEMP%`、或 **gitignore 的** `_local_test/` 下写 fixture；测完删除 |
| 汇报 | 输出结构化测试报告（模板见下） |

**若必须写一次性验证脚本**：放在 `_local_test/`（已 gitignore）或系统临时目录，**不得**提交、**不得**改 `tools/` / `autores/` 等业务路径。

## 环境对齐（测之前必做）

在报告中**显式写出**并让用户确认（未确认则标注「环境未对齐，结论仅供参考」）：

- OS / Shell（Linux bash vs Windows PowerShell）
- Python 命令（`python3` vs `py`）
- 工作目录、config 路径、数据库路径是否在 PVC/NAS
- 代理、`NO_PROXY`、端口、服务是否已启动
- 与用户截图/日志中的路径、版本是否一致

**默认假设：Agent 本地/沙箱结果 ≠ 用户服务器结果。**

## 标准流程（必须按顺序，不可跳步）

```
[1] 制定测试计划 → 列出要跑的全部项（一条 checklist）
[2] 只读准备       → 读代码/配置，不改源码
[3] 执行全部测试   → 跑完 checklist 每一项，记录原始输出
[4] 汇总           → 用报告模板填完 ALL 失败项
[5] 根因分析       → 每条失败：现象 / 可能原因 / 是否环境差异 / 是否需用户侧操作
[6] 向用户汇报     → 提交报告 + 「建议改法（如有）」；**等待用户明确指示后再改代码**
```

**第 6 步之前：零业务源码改动。**

## 测试计划模板（开始时复制并勾选）

```markdown
## 测试计划
- [ ] 项 1：（命令 + 预期）
- [ ] 项 2：…
- [ ] 项 N：…

## 环境
- 命令前缀：
- 工作目录：
- 与用户环境差异（已知）：
```

## 最终报告模板（全部测完后一次性输出）

```markdown
## 测试汇总

### 环境说明
（与用户环境差异、未验证项）

### 通过 (N)
| # | 项 | 命令/步骤 | 结果 |

### 失败 (M)
| # | 项 | 命令 | 退出码 | 错误摘要 | 完整输出位置/摘录 |
|---|-----|------|--------|----------|-------------------|

### 跳过 (K)
| # | 项 | 原因（缺依赖/需用户环境/未授权） |

### 根因分析（逐条）
1. **项 X**：现象 → 可能原因 → 是否源码 bug vs 环境/配置/操作问题 → 建议方向（**不直接改代码**）

### 建议改动（可选，供用户拍板）
- 改动 A：…（影响文件、风险）
- 改动 B：…

### 需用户确认
- [ ] 是否授权按上述建议修改源码？
- [ ] 是否在您的服务器上复测同一命令？
```

## 错误处理原则

1. **先收集，后判断**：所有失败项跑完再分析，不因第一条失败就停测（除非后续项强依赖且无法继续）。
2. **区分四类**：源码 bug / 环境差异 / 配置错误 / 用户操作或数据问题——每类处理方式不同，不得混为一谈。
3. **用户已提供的日志/截图优先**于 Agent 本地复现结果。
4. 本地复现失败但用户环境成功 → 结论写「未在用户环境复现，不建议仅凭本地结果改代码」。

## 与用户沟通

- 汇报时用完整句子；失败项附**可复制的命令**与**关键错误行**。
- 结尾只问：**要改哪些、是否授权改源码、是否在您的环境复测**——不要默认动手改。
- 用户说「回退」「别改」→ 立即停止一切源码修改，仅保留测试报告。

## 反例（禁止）

```
❌ 跑 to_csv 报 KeyError → 立刻改 to_csv.py 的 print
❌ Windows 没有 bash → 改 start.sh 适配 Windows
❌ 本地 database locked → 改 client.py 加 WAL 降级
❌ 测 PD 落盘 → 边测边改 scrape 函数「因为 bash 陷阱」
✅ 跑完 colocated + PD + 入库往返 + shell 语法检查 → 汇总 3 个失败 → 问用户改哪条
```
